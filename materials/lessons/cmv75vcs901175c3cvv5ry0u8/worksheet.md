# Lesson 225 — Compare Two Tools Fairly
Emmanuel Corels Academy · Practical AI for Everyday People

Use the same source notes and brief to compare two available assistants for a public-information drafting task. This kit is self-created fictional course material, not a real event or a report of tested product performance. Tool A and Tool B are evaluation labels; no brand or account is implied.

## Files and preparation
Open `cases.csv` and the matching `source-*.txt` files. Open CSV files with UTF-8 encoding and a comma separator in LibreOffice Calc; widen columns and enable text wrapping. Save your working copy as Fair_Comparison.ods if desired. Use Writer or a plain document editor for notices. No special spreadsheet formulas, macros, downloads or paid account are required.

The complete case is an Academy practice variation. Its 14:00 start time is explicitly supplied for that case only. The missing-time case and conflicting venue names match the authored lesson. Never transfer a confirmed field from one case into another.

## Exercise
1. Choose two available assistants. Fill `feature-record.csv` from actual visible settings. Unknown means unknown; a disabled retrieval instruction is not proof a tool cannot retrieve. If you cannot establish comparable retrieval conditions, record the limitation and avoid claiming a controlled comparison.
2. Open `task-brief.txt`. For each case, copy its entire source unchanged after the identical brief. Keep the same instructions and source in both tools. Use a fresh conversation or record unavoidable context differences. Never supply private information.
3. Before submitting, start a timer. Record setup separately from generation, source checking, correction and formatting in `time-record.csv`. Pick one unit (seconds) and one timing convention before starting. Do not fill durations from estimates or the lesson narration.
4. Save each first response unchanged as a separate local text file. Record the filename and a copy of the exact input in `run-record.csv`. A generated draft is not evidence. Keep all runs, including repeats and failures.
5. Compare each response line by line with its own opened source. Apply `rubric.csv` independently to each response. Quote exact defects in `correction-log.csv`, preserve the original, then save a separate corrected copy.
6. Check word count using the same editor and convention for both outputs. The requested range is 90–120 words; labels within a returned draft count. Document any external notes separately.
7. Repeat the missing-time case once per tool if available. Append new rows and artifacts; do not replace or cherry-pick the originals. A feature unavailable in an account is a workflow limitation, not automatically a writing-quality failure.
8. Open each final corrected artifact in its intended document or destination. Compare names, date, venue and time status, admission, 90–120word count and final formatting against that exact case source. Record its filename, actual destination, wordcount and human acceptance/hold result in `final-acceptance.csv`. Apply this same destination inspection to the manual route. Leave review results blank until performed; unresolved facts keep publication on hold.
9. Complete `decision-record.md` using observed outcomes and the whole task's effort. State which task, cases, accounts, date and settings your conclusion covers. Do not infer a universal winner from three cases.

## Check and manual fallback
Use `answer-guide.md` for source-grounded checks, not as a desired tool response. If either assistant is unavailable, copy confirmed fields into `manual-notice-template.txt`, mark unresolved fields explicitly, and edit for readability. Leave publication on hold until a human confirms missing/conflicting fields. Nothing in this kit sends or publishes a notice. Record manual-route effort too.

## Teaching examples and provenance
The saved lecture describes Tool A adding an unsupported time and choosing a venue, and Tool B flagging uncertainty but needing length/readability edits. These are the authored teaching scenario, not measured results from current tools. This kit deliberately leaves all actual run outcomes, ratings, scores, timings and account features blank. Your real observations may differ; preserve them honestly. Never edit a tool's output to force the narrated pattern.
