# Export, inspect, revise, export again
1. Read approved-source-pack.md. Mark words/facts/conditions/source note that must remain. Keep date/time/location/contact placeholders visible. Never invent missing event details.
2. Build the short document in a real editor using briefing-outline.md. Apply meaningful title/heading styles and a logical order. The final file should expose structure, not only large or bold text.
3. Make body text comfortable for the intended audience and headings larger. Choose a simple reading path and avoid crowding. There is no universal font-size answer.
4. Export the actual file. Open that export, view at normal and enlarged size and on a smaller viewport where available. Record viewer, scale and actual clipping/wrapping/overlap/scrolling observations in export-review.csv. A visual mock-up is not proof that a PDF reflows.
5. Inspect actual foreground/background colors in the exported artifact. Measure contrast with an available checker: the lesson generally uses 4.5:1 for ordinary text, 3:1 for large text, and 3:1 for meaningful controls/graphical objects against adjacent colors. Distinguish a required threshold from a measured sample ratio. Mark measurements not yet performed as Pending, never Pass.
6. Inspect the actual export's heading relationships, tags or reading-order panel if available. Expected sequence: Title, Purpose, Details, Actions, Contact, Source note. Check that decorative elements do not interrupt it. A manually typed order list is not proof of the exported tag tree.
7. If using a meaningful image/chart/diagram, include a nearby text equivalent or useful description. If there is no meaningful visual, record Not applicable with that reason. Never invent a chart just to populate a check.
8. Complete the concise-wording exercise while preserving conditions and source note. Make the five-slide practice deck if appropriate, then inspect actual slides one at a time and their exported sequence.
9. Manual fallback: open and enlarge every exported page, read in sequence, inspect actual colors, and use keyboard navigation or a screen reader where available. Ask a real reader to find the main action without explanation, and record genuine feedback only. If unavailable, keep that check Pending rather than inventing feedback.
10. Revise the source, export again and repeat checks on the new artifact. If a check fails or cannot be verified, record the exact issue and next action; use a simpler accessible format when needed. Do not mark an untested export finished.
