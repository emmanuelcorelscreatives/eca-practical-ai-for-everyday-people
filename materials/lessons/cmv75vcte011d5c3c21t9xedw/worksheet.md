# Lesson 226 — Measure the Whole Task

Emmanuel Corels Academy • Practical AI for Everyday People

## Goal and supplied evidence

Compare a checked, ready-to-use result, including checking, correction, transfer and recovery time. These self-created community-garden materials match the authored lesson. The supplied times and draft/failure examples are **illustrative values from the lesson**, not measurements collected from a model, device or person during kit preparation. No personal data or live external action is required. “Friday, 15 May” is a practice date; do not infer a year.

## Set the finish line first

Use `01-source-notes.txt` unchanged for both methods. Require (1) all four source points, (2) preserved names/dates/quantities, (3) an explicitly unknown owner rather than a guess, and (4) a usable action list. Use `acceptance-checklist.csv` to record observations. A quick draft is not a finished task.

## Run your own comparison

1. Open a fresh copy of the blank timing and artifact-log CSVs in a spreadsheet or notes tool. Record method, tool/version and the exact input/prompt. Save the evidence in your own new practice folder.
2. Start elapsed timing when opening the usable input, **before** preparing an instruction. Stop only after checking the final destination artifact. Include blocking waits. Hands-on effort, if also measured, must have a separate label.
3. For the assisted route, use `02-prompt.txt` and all source notes with an available authorized tool, or inspect the clearly labeled authored draft fixture without claiming you ran a model. Save an actual output unmodified if you run one. Mark it unverified.
4. Compare each draft line to the notes. The supplied draft fixture drops the unknown-owner label and the rain contingency. Log corrections; do not invent an owner or deadline. Save before/after copies.
5. Copy into the intended action-list destination, fix numbering and emphasize the unknown owner. Inspect the destination, not just the chat or source editor. Mark pass only after all four checks succeed.
6. If an attempt is unusable, keep it and its spent time. Reopen the source, manually transfer four points, and check again. The failure fixture is a separate illustration; do not silently add its duration to the already supplied worked timing example. Count recovery once, without overlapping stage intervals.
7. Repeat manually from the same source with the same acceptance criteria. Do not reuse the assisted final as your manual starting point or weaken manual verification. Record the run order and possible practice effects; these two runs cannot establish a universal performance claim.
8. Sum all seven stage durations. Compare total and pass status together. Keep a failed attempt in the log even if the fallback later passes. Use `expected-checks.md` to check arithmetic and exercise answers, not to fill in invented personal measurements.

## Manual fallback without an AI account

Use source notes, a blank document, a timer and the checklist. Type each point separately, retain “owner not assigned,” copy into the destination and verify. The labeled draft/failure fixtures let you practice checking and recovery offline. They do not substitute for a real tool-speed benchmark.

## Keep the evidence

Save source notes, exact instruction, original draft, correction log, final destination artifact, stage times and final checklist together. The CSVs are interoperable materials, not claims that an ODT/ODS file or specific vendor interface was captured. In the video the artifact folder uses ODT/ODS names; learners may save those genuine formats from their own editor/spreadsheet if desired. Never rename CSV/TXT extensions to pretend conversion.

## Reflection

Which stage consumed the most time? Did checking expose a real omission? What would change if transfer were cleaner? Report only what this task and your actual observations support.
