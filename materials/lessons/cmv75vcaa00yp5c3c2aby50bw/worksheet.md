# Lesson 210 — Keep a Manual Recovery Route
Emmanuel Corels Academy · Practical AI for Everyday People

All names, enquiries, times and workflow states in this kit are fictional, self-created training data. There is no connection to a live automation, email service or model. No sending is authorized. The sample draft is prewritten training material illustrating the generated-draft state in the lesson, not proof of a real AI run.

## Start with the evidence
Open `Original-Inputs.csv`, `Approved-Event-Information.md`, `Saved-Instruction.md` and `Run-History.csv`. EVT-1047 is Samira Okafor’s enquiry received 15 October 2026, 12:40 UTC. ## Practise a connection interruption
1. In the fictional run history, find EVT-1047. Draft creation completed before the connection failed. Open `Drafts/EVT-1047.md` and compare ID and content with the input. This actual kit file is the exercise destination record; a status label alone is insufficient.
2. Compare every draft claim with the approved information. Keep the support-person gap visible. Finish only the remaining review/revision work. Do not create another draft because the overall run is incomplete.
3. Open `Recovery-Log.csv` in your spreadsheet application and enter the demonstrated row. Leave Reviewer blank until review occurs. Use `Expected/Recovery-Log-Awaiting-Reviewer.csv` only after your attempt.
4. For the fictional review exercise, compare `Expected/Recovery-Log-Approved.csv`. Lina Chen is the fictional reviewer. “Approved draft retained; not sent” describes this exact state. It does not prove sending and does not approve a later edit.

## Practise a model outage
For EVT-1048, the model call is unavailable and no draft exists. Use `Manual-Recovery-Template.md`, the saved instruction and approved information to write a short manual reply. Identify it as manually written, retain missing-information labels, complete the checks and keep it unsent. Do not claim an AI output was generated or verified. `Expected/EVT-1048-Manual-Draft.md` is one possible answer, not unique wording.

## Practise loss of connectivity
Download/extract this complete kit to a new authorized local folder first. Confirm required documents and your chosen local applications open before disconnecting. A file being listed in a cloud folder does not prove it is available offline. If files/applications are unavailable, record the interruption and pause; never promise offline completion. This kit’s Markdown/CSV files are ordinary portable files, not an imitation of Word, Excel or a provider’s run history. The native Office companion files contain the same self-created exercise content; no vendor execution is claimed merely by supplying them.

## Document and reconcile
Complete the seven sections of `Manual-Recovery-Route.md`. Identify recovery owner, evidence checker, reviewer and platform administrator. If ownership is unclear, pause. On return of service, compare the stable ID against actual destination records and the recovery log **before** choosing a provider-specific pause, cancel, skip or replay action. There is no universal replay button or automated duplicate-prevention mechanism in this kit.

## Success checks
- EVT-1047 resumes at review; its existing draft is not duplicated.
- Step-free access is supported; support-person admission remains unresolved.
- Reviewer is blank before review; after fictional approval it is Lina Chen, with sending still absent.
- EVT-1048 has a manually written draft; no fictitious model result is claimed.
- Return action remains “Do not replay; reconcile first.”
- Offline availability and permission assumptions are tested, not presumed.

Use fictional input only. Do not copy private data to a replacement service. This lesson stops at manual recovery and reconciliation; Lesson 211 covers choosing a small useful automation.
