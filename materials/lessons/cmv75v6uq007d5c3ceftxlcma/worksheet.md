# Version Prompts and Keep Working Examples

Emmanuel Corels Academy — Practical AI for Everyday People, Stage 8, Lesson 46.

This kit preserves the lesson's fictional seed-sorting example and its v1 Current/v2 Draft distinction. The 2026-10-13 revision date is the authored example date, not a claim that these files were published then. No account, purchase or external message is needed. All data is self-created course practice material.

## Open the working record

1. Open `Event Reminder v1 CURRENT 2026-10-13.txt` in any ordinary text editor. Read the required inputs and four quality checks.
2. Compare `supplied-notes.txt` and `supplied-output-v1.txt`. The output is reproduced from the lesson as a supplied teaching example, not evidence of a new assistant run. Its content body is 30–60 words, includes all six input fields and no extra facts. The repeated date is a minor recorded weakness.
3. Keep the exact input and checked output together. The claim is **Successful for this input**, not universal reliability.
4. Read `Event Reminder v2 DRAFT 2026-10-13.txt`. Its only instruction change is: “State each logistical detail once unless repetition prevents confusion.” It has no checked v2 example. Keep v1 Current.
5. Open `CHANGELOG.txt`; check version, revision date, successful example, known weakness, change and next test. The files provide a portable fallback when built-in history is unavailable.

## Practice without overwriting the working copy

Copy the two version records to your own folder. First save the unchanged v1. Make a draft v2 by adding only the repetition instruction. Record its date, reason and next test. Do not rewrite or remove v1's limitation. If using an assistant, submit `prompt-v1.txt` with `supplied-notes.txt`; save its actual answer separately and apply the checklist yourself. Responses can differ; do not relabel the supplied answer as a live result. If offline, draft the reminder manually using the same inputs and checks.

On a phone use an ordinary note: mark v1 Current, keep its input/output and weakness together, and store v2 separately as Draft. Pin/archive controls and history vary by app; do not assume automatic restoration. No particular vendor or subscription is required for this exercise.

## Completion check

- Exactly one Current version; v2 remains Draft until checked.
- Date is unambiguous YYYY-MM-DD.
- Exact successful input and output saved together.
- Known weakness remains visible.
- One narrow change and an explicit next test are recorded.

`blank-revision-record.txt` is reusable for your own tasks. `answer-key.md` explains expected distinctions. Lesson 47 extends testing to different inputs; this lesson does not claim those tests have passed.
