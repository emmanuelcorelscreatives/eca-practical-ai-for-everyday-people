# Lesson 233 — Share a Workflow So Someone Else Can Use It

This permission-cleared, self-authored practice pack uses a fictional community event. No message has been sent, account accessed, or sheet published. The example draft is a written teaching fixture, not a claimed AI response. The completed result is still subject to human review.

## Start here
Open `00 Workflow Guide.txt`. Work in a separate copy of this folder and keep the approved fictional source unchanged. Open `01 Approved Event Brief.txt`, `02 Reusable Instructions.txt`, `03 Information Sheet Template.txt`, and `04 Review Checklist.txt`. The Drafts folder contains an example to compare after your attempt. Any plain-text editor can open these UTF-8 files. A suitable assistant is optional; the manual route needs no account, network, installation, payment, or code execution.

## Exercise A — normal handover
Give another learner the guide and a copy of the files, without a spoken tour. Ask them to inspect the source, complete the required-input check, prepare a draft using the reusable instructions or manual route, save their own copy in Drafts, compare every fact to the source, and record approval as NOT YET APPROVED. Do not contact the example addresses. Record actual questions and observations in `independent-test-record.csv`; blank fields are deliberately unclaimed. An AI draft may vary in layout but must preserve every confirmed fact and display the missing optional description. Compare with `expected-checks.md` only after trying.

## Exercise B — missing required time
Use `Tests/Missing Input Test.txt` instead of the normal source. The operator must stop, without borrowing the normal case's time or inventing one. Use `Tests/Missing Input Response.txt` as a clarification draft. Do not send it. Only the fictional owner could approve the offered “To be confirmed” alternative; that approval is not supplied. Record whether the operator stopped and what question they asked.

## Exercise C — manual fallback and transfer
Pretend the assistant or connection is unavailable. Copy only confirmed source facts into the blank template. Use the same checklist and human approval boundary. Ask another operator to follow your own adapted workflow, then repair unclear steps based on their actual questions. Do not record a test as completed unless someone actually performs it.

## Sharing practice
Use `sharing-and-cost-checklist.md`. Select a recipient and minimum suitable access on a local planning worksheet only. No access or external share is performed in this pack. For actual systems, inspect current account/organization permissions before sharing. Keep credentials, private notes and attendee details out.

## Deliverables and success criteria
Keep a separate draft, completed content checklist, unapproved status, manual-fallback draft, missing-time clarification draft, and truthful test record. Success means another person can start from the guide, preserve confirmed details, identify the optional gap, stop on missing required input, and reach the same review standard manually. Correct any guide gap before handing it over. Lesson 234 moves to a capstone brief; this lesson stays focused on transferability.
