# Know What You Are Uploading — Lesson 13

Emmanuel Corels Academy · Practical AI for Everyday People · Stage 3.
All names, contacts, circumstances, messages and event data here are fictional teaching examples authored for this course. No private user files were used. Sample contacts use reserved example.invalid and fictional telephone ranges.

## Purpose
Practice deciding what a public event setup checklist needs before submitting information to an AI tool. This is a pre-upload review lesson, not a promise that removing a name anonymizes data or that every service has identical handling.

## Files
`Riverside_Event_Source.odt` is the intentionally risky local source: visible sections, a real ODF comment and fictional author metadata. `Riverside_Event_Working_Copy.odt` is a byte-identical working copy. Keep the original unchanged. `Riverside_Clean_Setup_Notes.odt` and `clean-notes.txt` contain only task facts. `prompt.txt` combines those facts with the lesson's instruction. `worksheet.md` is your exercise; `answer-key.md` and `expected-checklist.md` support checking. `verify-kit.py` checks the actual packaged examples locally.

## Practice
1. Open only these new Academy sample files in your local document editor. Inspect the visible source and decide which facts support a public setup checklist.
2. Review comments, revisions, document properties, author information and embedded content. This sample includes one comment and fictional author Mina Okafor; it contains no tracked revisions or embedded objects. The broader scan still matters. Exact menu locations vary by editor/version; do not assume a screenshot or this guide proves your own file is clean.
3. Complete the worksheet before consulting the key. Keep the original local and use the working copy for any experiment. Removal of comments, revisions or metadata can be irreversible.
4. Compare the supplied clean notes to the task. They retain the quiet-area requirement without identifying who requested it or explaining why.
5. Optionally paste ONLY `prompt.txt` into an AI service you are permitted to use. Do not upload the original ODT. This kit contains no upload automation or credentials. Check your current service/account/organization settings and authority first; if uncertain, work locally instead.
6. Compare every generated action to the clean notes. Check quantities and time, absent excluded information and absent invented specifics. The illustrative answer key is not a claim of a completed AI request.
7. If AI use is inappropriate, create the same checklist manually in a regular local editor using only permitted facts.

Run `python3 verify-kit.py` from this directory. It needs Python 3's standard library only. It inspects the exact sample package and is not a general-purpose privacy scanner or a certification of arbitrary documents.

Privacy settings for training/model improvement, history, retention, human review, sharing and connected apps are separate questions. Account type, plans, policies, region and administrator rules may change. Consult the actual current service and your organization; possession of someone else's message is not permission to upload it.
