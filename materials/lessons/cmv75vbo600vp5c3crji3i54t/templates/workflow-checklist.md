# Workflow Checklist — Community Event Update
Version:1.1 · Owner:[name or role] · Last tested:[actual date]
Purpose: create a checked event-information draft from approved notes.
Trigger: approved event notes arrive. Final result: a named reviewer accepts the formatted draft.

## Required inputs
Event name; date; start and end time; location; audience; approved description; accessibility information; contact; permission confirmed by; contact approved by. Record the authoritative source/approval for each. Empty fields stay blank. Leave out private attendees, personal phone numbers, credentials and unrelated internal notes.

## Stop before generation
If any required fact is missing or contradictory, request clarification using the note template. Do not guess. Await the source owner. No finished information sheet is created for a blocked case.

## Tool sequence
1. Complete and validate the input form.
2. Generate a clearly labelled draft using the reusable prompt and only permitted notes.
3. Compare names, dates, numbers, meaning, completeness and additions with the source. Record corrections; assistant output is not evidence for itself.
4. Copy only checked wording into the document template.
5. Inspect the actual file for missing sections, clipping, spacing and filename. Keep Draft status until a real reviewer approves it.

## Measure and record
Write expectation before execution. Time from preparation to actual stop, including handoff, checking, correction, formatting and recovery. Record corrections, outcome, limitation and unresolved questions. Separate complete and exception cases.

## Manual fallback
Use the same form and validation. A person copies approved facts and writes the description. Independently compare every field with its input, inspect the actual formatted file and retain the human approval boundary. Do not send or publish.
