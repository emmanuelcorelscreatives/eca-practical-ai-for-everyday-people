# Build a Representative Test Set — Lesson 224

Emmanuel Corels Academy · Practical AI for Everyday People

All community events, people and notes here are self-authored fictional practice fixtures. Nothing here reports a real event, external action, model run or timing observation. The original lesson pronounces dates with ordinal suffixes; these sheets retain the equivalent written calendar dates used by its screen prompts.

## Prepare before testing

Open test-case-sheet.csv in a spreadsheet, or copy its eight headers into a document. CSV does not preserve formatting: turn on text wrapping and widen columns. The four supplied rows preserve the lesson’s typical, ambiguous, incomplete and conflicting source inputs. Expected behavior is written before any output is obtained. Keep these original notes separate from instructions and generated artifacts.

Read fixed-instruction.txt. Use exactly that instruction for every case; change only the source input. A generic AI assistant of your choice may be used. No particular vendor, account or purchase is required; interface details differ. Do not upload private data.

## Run and preserve

1. Start a timer before submitting the fixed instruction and exact case input.
2. Save the actual unedited response as T01-output.txt, A01-output.txt, I01-output.txt or C01-output.txt. Mark it GENERATED OUTPUT — NOT SOURCE EVIDENCE. Do not present the supplied expected checks as observed model output.
3. Compare every action, owner, date and claim against the original notes and expected checks.
4. Stop the timer after inspection; record your own run-plus-inspection time consistently as mm:ss.
5. Write what actually happened, choose Pass or Needs work and name any exact correction. Preserve a failed response before trying corrections. Do not rewrite expected behavior to match the result.

The lesson’s 00:52, 01:18, 01:06 and 01:11 are prepared demonstration records, not a benchmark or measurements obtained by this kit. Your elapsed-time cells intentionally start empty. Four passing cases do not prove universal reliability.

## Manual fallback

If the assisted route is unsuitable, read each source yourself. Copy only supported facts into an Action / Owner / Due date table, enter Needs clarification where necessary and list contradictions separately. Keep the two C01 statements visible until a person confirms them. Record why you used the fallback. No email, booking, publication or other external action is performed by this exercise.

## Extend without changing the lesson

Use coverage-and-new-cases.md to design longer notes, unusual wording, multiple requests or an outside-scope request. Add languages only where relevant and check meaning with someone competent. Do not use a fixed percentage recipe. Keep this lesson focused on constructing cases; broad productivity claims and tool comparisons belong elsewhere.

## Self-check

Could another learner find each exact input, prewritten expectation, original artifact, actual observation and correction? If yes, your sheet is reproducible. Read expected-checks.md for an answer key, keeping it separate from recorded results.
