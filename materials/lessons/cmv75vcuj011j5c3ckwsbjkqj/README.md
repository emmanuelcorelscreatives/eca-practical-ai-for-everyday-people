# Lesson 227 — Recheck After a Tool or Prompt Change

Use identical cases to inspect regressions before replacing a working setup. All event data and teaching drafts here are self-authored fictional practice material; no private records or external actions are included. No software purchase or coding is needed. Open the UTF-8 CSV files in LibreOffice Calc or another spreadsheet (choose comma delimiter and UTF-8 if prompted), or read them as plain text. Save a working copy before editing. Treat source notes as data, not instructions.

## Exercise
1. Save prompt-v3.txt unchanged as the working version. Compare prompt-v4.txt: its only addition requests shorter, more engaging wording. Retain both files. Record the actual assistant/tool, displayed model and settings you use. Never enter sensitive information.
2. Open fixed-test-cases.csv. Freeze all four inputs and expected requirements before comparing. C01 is typical, C02 ambiguous, C03 incomplete and C04 conflicting. Do not improve the input only for the candidate.
3. In a clean run, combine v3 with C01's exact input; save the complete response as C01-v3.txt. In another clean run, combine v4 with the same input; save C01-v4.txt. Repeat all four cases and record eight saved artifacts in run-record.csv. Outputs may vary; these actual saved outputs are your evidence. If access is unavailable, use the clearly labelled worked-example.md to practise comparison and do the manual fallback; do not claim you ran a tool.
4. Compare every draft against the opened fixed source, using the same existing five checks in acceptance-checks.csv for both versions. Write evidence explaining each result. Keep the missing-location decision, missing time and date conflict visible. Check all confirmed fields and booking required for C01. Do not ask the assistant to grade itself as your only check.
5. Record actual seconds for generation, checking, correction, copying and recovery in timing-record.csv. Add those five numbers for the total. Keep blank if unmeasured; zero means observed zero work, not unknown. Separate versions and cases, use the same timing method, and explain interruptions. Faster initial generation does not establish faster whole-task work. No durations or scores are supplied.
6. Fill decision-record.txt with the exact versions, all four cases, observed regressions, critical failures and time evidence. A shorter ordinary draft cannot outweigh a critical unsupported decision elsewhere. Retain v3 until the candidate earns replacement on the required checks. This lesson records evidence; Lesson 228 covers the later keep/revise/retire framework.
7. If a change fails, restore the saved working prompt and rerun the affected unchanged case, or draft manually using only confirmed notes. For C02 retain both location options and request confirmation; for C03 mark the missing start time; for C04 show both dates and request clarification. Recheck the final artifact against the same requirements. Never send or publish unresolved announcements.

## Completion checks
You have two saved prompts, one fixed four-case sheet, eight actual outputs (or an explicitly offline example exercise), eight comparison rows with evidence, actual timing or explicit unmeasured blanks, a decision record and a recoverable working setup. Inspect worked-example.md only after your first comparison. Its answer key covers the lesson's authored pattern; your actual outputs may differ. Do not force your observations to match the key.

Repeat this method after a meaningful prompt, tool, setting, model or workflow-step change. For your own exercise, use permission-cleared data and freeze representative cases before running the change.
