# Prepare, then inspect your brief
1. Read the worked brief. Identify its problem, beneficiary and four exclusions. Do not build the workflow.
2. In a copy of Capstone Brief.txt, choose your own recurring everyday problem, or reuse this fictional example. State a manageable input and inspectable output. Do not enter real private data.
3. Complete all twelve headings, including a job-based tool sequence. List required features without committing to a brand. Keep current costs, usage, measurements and approvals blank until verified.
4. Define six observable acceptance conditions. For each, state what would cause correction or a stop. Include traceability, unsupported fields, visible uncertainty, preserved meaning, file usability and final approval.
5. Plan normal and missing-information cases; distinguish an unknown action field from an absent required source. Do not run either case or claim results.
6. Specify a complete manual fallback and a named reviewer role with authority to stop. Save the brief in Workflow Files. Inspect that it opens and that someone else could follow the plan without access to your account.

Planning self-check: Are all twelve headings complete? Is external action separate? Are assumptions labelled? Are claims of savings, tests, live prices or approval absent unless actually evidenced? Compare against answer-guide.md.
