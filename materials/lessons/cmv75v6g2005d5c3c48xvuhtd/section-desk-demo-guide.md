# Section Desk v1.0 — reproducible section-processing practice

This optional working app complements the complete manual exercise in `worksheet.md`. It runs deterministic local rules for this six-section fictional pack. It is not an AI model or evidence of an external assistant response. Its generated notes are software-generated working examples, and checking them against the source remains your responsibility.

Open a terminal in `section-desk-demo` and run `python3 -m http.server 18833 --bind 127.0.0.1`. Open `http://127.0.0.1:18833/app.html` in a browser. Keep the server limited to this supplied exercise folder. Stop it with Ctrl+C when finished. This serves local static files only. The app makes no external request, uses no account, and stores no long-term conversation memory. No installation is necessary if Python 3 and a modern browser are already available. Without them, complete the manual ODT/table exercise instead.

1. Select S01. Inspect the unchanged instruction, empty checked handoff, and original source. The app checks the exact supplied ODT SHA before displaying the source text extracted from that ODT in `sections.json`.
2. Click **Process current section**. Compare the opened source passage with the generated local-rule notes. Expected audience: local residents and first-time gardeners. Assumptions: None. Evidence: S01, pages 1–2.
3. Only after reading the source, click **Record source comparison: checked**. This records your decision, not an independent automated verification. The handoff preserves the shared goal, audience, completed sections and evidence location.
4. Select S02 and process it. The S01 audience and location must remain in the handoff. Expected result: a confirmed step-free route to the main garden area; accessible toilet missing confirmation; no guarantee of every activity being accessible or a parking space.
5. Check and process S03–S06 in source order. Keep the advanced seed-saving workshop / first-time audience mismatch unresolved. Public opening is 10:00; volunteer arrival is not specified. Keep draft status, privacy constraints and activity-specific access questions.
6. After all six source comparisons, click **Compose final synthesis**. It refuses synthesis until six sections are checked. Read the synthesis instruction and six checked-note identifiers; then click **Synthesize checked results**.
7. Verify the generated draft against all original sections. Expected date: 17 May 2030; public opening 10:00; draft status; narrow route statement; advanced workshop qualification; visible pending toilet, volunteer-arrival and activity-access details. Citations locate passages and do not prove accuracy. A successful output does not replace this review.

The local rule map is deliberately limited to these exact fictional sections. It is not a general document reader and does not promise to handle arbitrary uploads. The app uses the complete supplied shared-instruction.txt verbatim. Editing the displayed task stops processing, recording a checked result, composing and synthesis. It preserves the edit for explicit reconciliation instead of silently accepting it. Each checked section retains exact source-linked facts, notes and open questions. The handoff is derived from those retained records, including the date, venue, public time, parking limitation, draft/privacy conditions and unresolved details. Editing that handoff causes the next check or synthesis to stop explicitly; the app never silently overwrites edits. Restore the generated source record or use the separate manual trainer and editable handoff template for free-form changes. A later section requires the retained checked S01 audience, and synthesis requires six complete checked records plus an unchanged validated handoff. Refreshing resets the exercise; record your work separately in the supplied handoff template.

All original 23 practice file roles are retained. The worked handoff now explicitly links the venue to S02, correcting its evidence location without changing the fictional source pack. The additional app includes its full source code, six exact ODT fixtures and extracted source map. No private document, fabricated remote response or named vendor interface is included.
