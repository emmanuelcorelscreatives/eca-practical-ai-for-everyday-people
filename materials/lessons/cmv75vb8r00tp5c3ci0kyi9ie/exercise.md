# Practical exercise
1. Open a COPY of the fictional restricted register. Classify each field as identity, private request, internal note or potentially approved event fact. Do not upload the register to an assistant.
2. Start a blank document. Extract only needed, approved facts. Compare with approved-public-facts.csv. Public contact is the approved fictional general event address events@riverside.example (a reserved .example teaching domain, not a real mailbox). Parking must remain “Not supplied — confirm before publication”; never invent a parking promise or use a private personal contact. The approved accessibility sentence is a venue fact, not an attendee request.
3. If using an approved assistant, attach ONLY the clean source and use prompt.txt. Otherwise draft manually from the same source. No existing private files or real accounts are required.
4. Inspect unsafe-draft.txt. Mark each private disclosure, internal opinion or unsupported addition. Explain why saying “Attendee 01” would not automatically anonymize a rare request or role.
5. Produce a corrected public announcement. Retain the supported event facts, approved general address and visible parking missing-information marker; it remains a teaching draft pending confirmation, not a ready-to-post real announcement.
6. Duplicate announcement-inspection-copy.docx before opening desktop Word. Use File → Info → Check for Issues → Inspect Document. It contains a fictional comment, tracked deletion, document author metadata, and hidden text. Review categories and findings on your own installed version before removing anything. Preserve the original exercise file. If your Word version lacks Document Inspector, do not claim the file is clean: use an authorized desktop version or make a fresh visible-only document and still inspect the final artifact.
7. In the workbook inspect hidden sheets, hidden columns, comments and document properties. The hidden sheet and comment hold fictional internal content; they are deliberately excluded from the public-facts file. CSV exports cannot preserve those hidden workbook features, which is why both forms are supplied.
8. Check the public filename, selected file, permission audience, edit/reshare rights and attachments before any hypothetical sharing. Do not change a real link's permissions for this exercise. Fill release-checklist.md with actual observations; permission labels in the worksheet are proposed roles, not real cloud ACLs.
9. Export your corrected public draft as PDF, OPEN the exact exported PDF and check every visible fact, extra page and unexpected content. Preview it on a phone or narrow viewport. Another authorized person compares both directions: every public statement approved, no restricted field crossed over. No actual publication is requested.
10. Compare with answer-key.md and run python3 check-kit.py. A checker PASS proves the supplied package structure and exact expected sample facts only; your human file/permission review is still required.
