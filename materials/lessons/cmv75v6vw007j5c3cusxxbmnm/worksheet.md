# Test a Prompt with Different Inputs — Lesson 47

This permission-cleared Academy exercise uses fictional community-event notes. Nothing here is a real event or message. `events@example.org` is an illustrative address; do not send mail.

1. Open `prompt-v1.txt` and one file under `inputs/`. Paste the prompt followed by the unchanged notes into your chosen assistant. Start a fresh conversation for each case to avoid carrying answers between runs. Do not add hints or fill the blank date. No account, paid product or external action is required for the manual route.
2. Save the actual response locally in a new file. Record the assistant name, visible version if available, date, prompt version and case in `test-record.csv`. Never present provided illustrative text as an observed assistant response.
3. Compare all six required fields against the input, not against fluent wording. Check format, unsupported additions, gaps, conflict handling and the boundary between source notes and operating instructions.
4. Run all three cases with unchanged version one before revising. Record observed weaknesses even if version one happens to handle the missing date safely.
5. Open `prompt-v2.txt`, record your actual revision date, and rerun all three ORIGINAL cases in fresh conversations. Compare against `expected-behavior.md`. Wording can differ; the factual and uncertainty-handling requirements cannot.
6. Preserve both prompts, unchanged inputs, actual outputs and completed record together. Rerun after changing tools or settings. Three passing examples establish only behavior in those runs.

Use `manual-fallback.md` if no assistant is available or a result fails. The next lesson uses your stage work to create an everyday prompt kit; this exercise does not replace that project.
