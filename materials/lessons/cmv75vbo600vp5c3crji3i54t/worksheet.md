# Project 8: Build Your Repeatable Workflow
Emmanuel Corels Academy · Practical AI for Everyday People · Lesson 192

Turn a low-risk, one-off community-event update into a documented process another person can follow. Use an assistant and a document editor as two distinct tools. Any suitable apps can be used. The event fixtures and reference answers are Academy-authored fictional practice, not real events or services. Separately, observed/ and records/actual-controlled-results.json retain genuine configured-assistant and Writer test results from12November2026. Those are software/Codex-operated tests, not human labour measurements or human approvals.

Start with `templates/workflow-checklist.md`, `templates/input-form.md`, `templates/prompt-library.md` and `templates/information-sheet.md`. The workflow starts with approved notes and ends with a named human accepting a reviewed draft. Sending, publishing, purchasing and other external actions remain outside this exercise under separate human control.

## Do the project
1. Read the checklist and fill the form from one supplied input, copying facts exactly. Keep supplied facts apart from generated wording. Confirm source permissions and omit private attendee information, personal contacts, credentials and unrelated internal notes.
2. Write expected behavior in `records/blank-test-record.csv` before running the case. Begin a real timer before preparation. Include copying, handoffs, checking, correcting, formatting and recovery until the real stopping point.
3. For complete Case A, submit only its permitted notes with the reusable instruction. Preserve every name, date, time, location and contact. Compare every detail with the source. A draft cannot verify itself. Transfer only checked wording into the file template and inspect the actual file for missing sections, clipping, spacing and correct filename. Keep Draft status until actual human approval.
4. For Case B, stop because accessibility information is blank. Produce a clarification note, not an information-sheet draft. Never invent a ramp or promise. For Case C, show both conflicting dates and their sources and request an authoritative answer. Do not choose either date.
5. Complete separate records for all three cases. A safe stop is a pass when it matches the prewritten expectation. Compare complete runs with comparable complete runs; do not average stopped exceptions into a savings claim.
6. Try the manual fallback with the same inputs, checklist, checks and template. Write the short description yourself and check copied digits and meaning independently.
7. Give the pack to someone who did not build it. Record genuine questions, update unclear fields (including Contact approved by), increment the version and retest. The kit contains version1.1 input fields reflecting that authored lesson refinement.

## Acceptance evidence
Deliver the checklist, prompt entry, templates, all three actual test records, actual measured times, checked outputs or explicit stops, unresolved questions and reuse guide. Do not mark sample answers as your own observed execution. Every consequential fact must trace to an input; every unsupported gap remains visible. Completion of a practice check does not authorize publication. Case B and C facts remain unresolved until an actual source owner answers.
