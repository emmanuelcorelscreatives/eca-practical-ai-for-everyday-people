# Lesson 212 — Build the Input and Draft Steps

Use the three fictional garden requests supplied here. G-101’s date, area, category, routine urgency and uncertain wording match the lesson. G-102’s herb-bed location/description and G-103’s south-path location/category are self-authored practice details where the narration does not specify exact values. They are training records, never real submissions.

## Practice
1. Open `workflow-practice-board.html` locally in a browser. No account, network connector or paid service is required. The board is actual working Academy training software, not Google Forms/Sheets/Docs or a live AI service. It uses deterministic draft assembly to make field behavior inspectable; it does not call a language model.
2. Inspect the six fields and the three source rows. Keep one request per row; do not add personal data. Reported urgency is the fictional submitter’s report, not an expert judgment.
3. Select G-101 and inspect the trigger and mapping screens. Six green indicators mean fields are available, not validated. Only matching field labels map; no owner, row-number or unrelated metadata is mapped.
4. Read the four-part instruction: task, source fields, rules, output format. Use `instruction-template.md` in an available assistant if you want a real AI draft. Keep descriptions separate from instructions.
5. Inspect the assembled source block, then choose **Test draft only**. Compare all six facts and check that “appears blocked” remains uncertain. This local simulator is not proof that a real assistant will obey instructions.
6. Switch to G-103 and test again. Its urgency is genuinely empty. Confirm “Missing information” and the identified gap appear without inferring urgency from standing water.
7. Choose **Save local review copy**. It preserves the complete draft in this browser session, not Google Docs or a remote folder. The document title contains the source ID, all eight headings remain and the status is “Generated draft — not reviewed.” Saving is not approval.
8. For the manual route, copy one fictional CSV row into the reusable template, use an available assistant, and paste its entire output into a review document you control. Keep missing-information and draft-status sections. Do not send, publish, notify or grant unnecessary permissions.

## Stop boundary
Lesson 212 ends after input and draft. Do not build validation routing, approvals, error handling or final actions here; Lesson 213 covers validation and review. If generated prose changes a meaning, correct the instruction or draft. Do not invent a correction to unclear source evidence.
