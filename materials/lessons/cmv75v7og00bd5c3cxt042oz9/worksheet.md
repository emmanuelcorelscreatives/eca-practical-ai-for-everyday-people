# Open the exported file

Allow 20–30 minutes for hands-on practice beyond the 12-minute lesson. Work locally with the fictional kit. Record actual observations; a successful export notification is not a review result.

1. Read the brief and mark the required public facts, two staff quantities, full walkway instruction and missing fields. Copy review-log-blank.csv for your own results. Keep the answer key closed.
2. Compare instruction-and-draft.md with the brief. Find the meaning change, wrong quantity and incomplete sentence. Identify the internal note and missing information. Recalculate refreshments independently using a calculator or spreadsheet; record inputs, operation, result and units.
3. Open event-pack-corrected.rtf in your word processor. Inspect both pages. Save an editable local copy. For the controlled first export choose only the current first page if your editor offers that option; otherwise export all pages and explicitly record that you could not reproduce this trap. Save as Riverside_Repair_Cafe_Event_Pack_v1.pdf. Close the preview, then open that saved file in a PDF reader. Record the file name, actual path, expected and found page count. Never invent a one-page observation.
4. Export all pages to v2.pdf. Open the newly saved v2.pdf rather than an old viewer tab. Inspect every page. Two pages alone is insufficient: verify all public facts, OR meaning, badges, headcount, and complete sentence. Log content mismatches separately from observed formatting defects. If your exporter creates an extra page, record it and adjust spacing without hiding or shrinking essential text.
5. Inspect every edge, bullet, line break, image if any, footer and paragraph at ordinary zoom. Enlarge text and inspect reading order. The plain RTF uses no illustrative image; if you add one, add meaningful alternative text when it conveys information. Use an available accessibility checker and record its actual findings plus its limits. Do not claim comprehensive accessibility from a checker pass.
6. Inspect comments, tracked revisions, properties and any hidden material in the editable file and in the final format. Remove editorial notes from the distributed copy; preserve the visible missing-time warning. If a feature is unavailable, record the limitation rather than a pass. Confirm your plain registration placeholder is not a misleading live link; if a real approved address is supplied later, test its actual destination then.
7. Test a phone-sized destination (actual phone viewer if available, otherwise honestly label a narrow-window approximation). Can you find date, time, venue, cost, registration, capacity and access without hunting? Check print preview for exactly two pages, useful margins and orientation. Record actual application and approximate zoom/width; do not claim phone testing from a desktop preview.
8. Correct your editable copy, re-export to v3.pdf and open it. Recheck the repaired areas and surrounding content, both pages and page count. A corrected editor file does not replace an old shared export. If layout remains unstable, rebuild the affected section using plain single-column paragraphs and a real page break, then export/reinspect.
9. Complete the reusable card with actual results, unresolved items and intended recipient. A practice placeholder is acceptable for this exercise but is not a working registration destination. Stop any actual distribution until needed facts, permissions and recipient selection are confirmed. The next lesson supplies the broader accept/revise/stop decision method.

Without an editor/PDF exporter: do steps 1–2 on the supplied text and complete expected checks in the log, marking export/destination/hidden-material fields NOT TESTED. This is a useful manual fallback, not a claim of final artifact inspection. To finish the full exercise, use a trusted available editor and reader later.
