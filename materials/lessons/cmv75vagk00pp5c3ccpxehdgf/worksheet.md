# Lesson 156 — Verify the Finished File

Emmanuel Corels Academy · Practical AI for Everyday People · Stage26

The fictional Community Learning Weekend fixture has five slides: title, agenda, chart, actions and sources. It uses only self-created evidence. No registrations are real personal data.

## Exercise

1. Keep `Community-Learning-Weekend_original-draft.odp` untouched. Work on a separate review copy. First open `opened-source-pack.md` and `workshop-registrations.csv`.
2. Open the original in an actual presentation editor. Confirm five distinct slides in order. Inspect every slide in edit view and presentation mode; record what you actually see.
3. On slide1, enlarge the subtitle box instead of reducing text to unreadable type. Confirm every line is visible with space around it. If necessary, shorten only the subtitle without changing meaning.
4. On slide2, separate the overlapping icon and second agenda item. Move the footer within safe margins. Inspect at normal size and a smaller preview.
5. On slide3, open the real underlying chart data. The original deliberately stores April48, May54, June60. The authoritative opened table is April48, May60, June54. Correct actual data and recheck all categories, values, units, labels and zero-based axis. Changing labels alone is insufficient.
6. On slide4, move all three action cards fully inside the slide. Read every sentence. Retain “Assumption: final room assignments not yet confirmed.”
7. On slide5, preserve the schedule source note and add the genuine self-created registration-table source note. Room assignments remain unconfirmed. Do not invent URLs or imply that an assistant independently verified a source.
8. Recount slides and inspect all text and sources. Export a NEW `Community-Learning-Weekend_checked.pdf`. A native LibreOffice-exported checked PDF is supplied. Re-export your own repaired copy and inspect it independently.
9. Open the finished PDF, not merely the editor. Confirm five pages. Check page1 subtitle; page2 alignment/footer; page3 corrected chart; page4 complete actions and uncertainty; page5 both sources and uncertainty. Check filename and extension.
10. Try zoom where supported and print preview without printing. Check paper boundaries, margins and labels. When practical, open the same PDF on another available device. This does not replace checking every page and does not prove complete accessibility.
11. If a feature is unavailable, inspect each exported or printed page manually and compare chart values and source notes. Record unavailable checks honestly. Do not mark anything complete from a generated claim alone.
12. Use `final-file-checklist.csv` and `correction-log.csv`. If any required test fails, fix the editable copy, export anew and repeat the checks. `known-defects-and-expected-checks.json` contains a teaching answer guide, not observations from an actual app session.
