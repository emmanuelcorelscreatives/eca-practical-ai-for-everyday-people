# Lesson 208 — Check Output Structure Before Continuing
Emmanuel Corels Academy · Practical AI for Everyday People

Open `validation-lab.html` in a modern browser. It works offline with no account, uploads, network requests, or external actions. It is a self-created Academy practice application, not a vendor product or an AI service. Its Create summary card is a deterministic practice transformation; it does not call a model. The three fictional inputs exactly match the lesson. Any generated draft still needs separate meaning, facts, permission and human approval checks.

Choose Normal, Missing date, or Invalid formats, then Run selected input. The real validation function checks presence and form before changing its in-memory review sheet. Failed records skip Save draft and appear in manual review. Run all three cases to populate the real run-history and portable log views. Nothing is saved to disk unless you choose Download log CSV. Reloading resets this practice session. The log received/resolved times are actual practice browser times, not historical event claims.

Use `worksheet.md` to predict outcomes first, and compare with `expected-results.json`. `practice-inputs.json` is a portable copy of the same three fixtures embedded in the offline app; no fetch is needed. `validation-log-template.csv` is blank for your own observed results.

Manual recovery: select a failed record, confirm a replacement against the fictional source card, edit the fields, and run again. The supplied source card authorizes **2026-11-06** and **normal** for these fictional examples only. This is training evidence, not permission to guess dates in real work. Each rerun creates a new history row; failed evidence remains visible. No real message, spreadsheet account, publication, purchase or consequential action is performed.

A date must use YYYY-MM-DD and be a real Gregorian calendar date (year 0001–9999). Identifier/title are non-empty text after trimming; priority is exactly low, normal or high. This lab deliberately does not validate email, numbers or factual truth because those are not fields in this lesson's example. Add task-specific checks before using a different contract.

Run history includes an Inspect preserved run selector: each saved snapshot shows the exact original input, Receive and Create summary outcomes, all validation reasons and the downstream result. The deterministic short draft is visible there even when the later save is skipped. Review sheet displays only drafts from passing runs. These are local in-memory artifacts, not external spreadsheet writes.
